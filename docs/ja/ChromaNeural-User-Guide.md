## 1. インストールと起動

公式 GitHub リリースから適切なパッケージを取得し、SHA-256 を一覧と比較します。インストールガイドの前提条件を満たしてください。固定された ICP SDK は同梱され、npm や古い開発環境は不要です。

Windows はユーザー別の版番号付きインストールフォルダーから Start-ChromaNeural.ps1 を起動します。Linux はアプリメニューまたは chromaneural。macOS は前提条件導入後に ChromaNeural.app を開きます。未署名ですが、OS 保護を全体的に無効化しないでください。

初回はリソース設定を選び保存します。保存だけでは本番ネットワークに参加承認されません。例はアカウントや私的データがなく、参加停止中です。

![設定保存後の概要、参加停止中。](../images/chroma-neural-overview.png)

保存済み rc.1 画像はデンマーク語で、rc.2 の言語選択は写っていません。**Oversigt** は概要、**Ressourcer** はリソース、**Aktivitet** はアクティビティ、**Login & forbindelse** はログインと接続です。手順ではこれら過去の表示名を訳と併記します。rc.2 は明示的な別言語選択がなければ英語で起動します。

ダッシュは確定値がないことを示し、残高ゼロや推定収益ではありません。左側でページを切り替えます。

## rc.2 クライアントの言語

単一クライアントが English、Dansk、Deutsch、Français、日本語、简体中文、हिन्दी に対応します。OS の言語にかかわらず、既定とフォールバックは英語です。サイドバーの言語選択でアプリ自身の表示を即座に変更できます。入力、ソーステキスト、接続 JSON、参加状態は維持され、言語変更で別のワーカーやネットワーク確認は開始しません。OS のファイル選択部品は OS の言語のままです。

GUI で明示的に選択すると、既存の `preferences.json` と同じ状態ディレクトリの `ui-language.json` にバージョンとロケールだけを保存します。既存設定のスキーマは変えず、別の状態ルートも作りません。次回起動時に選択が復元されます。設定がない、不正、大きすぎる、未対応の場合は、原本を書き換えず英語になります。後の明示的な保存では不正な原本を保全し、保存失敗時は現在の言語を維持します。

任意の CLI 引数 `--language` は、その起動だけの上書きで保存されません。Windows ランチャーは `-Language` を渡します。対応識別子は `client/locale-registry.json` で管理し、初期出荷対象は `en`、`da`、`de`、`fr`、`ja`、`zh-CN`、`hi-IN` です。将来の言語追加に必要なのは、同じメッセージキーを持つカタログと、表示名・数値書式メタデータを含む登録項目一つです。検証用の一時的な第8ロケールは出荷しません。

## 2. リソースと参加

![実際のリソース設定。この例では CPU 貢献を有効にしていません。](../images/chroma-neural-resources.png)

1. **Ressourcer**（リソース）を開きます。
2. 推論スレッド上限とメモリー設定を選びます。
3. アイドル時のみ計算するか、バッテリー時に一時停止するか選びます。
4. 対応プラットフォームではシステムトレイ動作を選びます。
5. **Gem ændringer**（変更を保存）、初回は **Gem og fortsæt**（保存して続行）を選びます。**Oversigt** で戻ります。

設定は上限でありハードウェア予約ではありません。記載の Windows 同梱 CPU プロファイルは CPU スケジューリング、推論スレッド、コミット済みメモリーを制御します。物理 RAM 全体／RSS は保証しません。制御付き Ollama、Linux、macOS、GPU 貢献は非対応であり、制限を強制できるプロファイルとして宣伝できません。

一般リソース共有は無効です。開始や一時停止でも、ジョブ承認、ノード参加承認、リソース制御を迂回できません。導入済み・未使用のハードウェアだけでポイントは得られません。

## 3. ログインと接続

![未読込の接続プロファイル。ブラウザーログインと API 確認は別です。](../images/chroma-neural-connection.png)

1. **Login & forbindelse**（ログインと接続）を開きます。
2. **Log ind med Internet Identity** で既存 Web アプリをブラウザーに開きます。自分の既存 ID を使い、セッションや復旧情報は共有しません。
3. Web アプリの API プロファイルをコピーしてクライアントに貼り付け、**Gem forbindelsesdata**（接続情報を保存）を選びます。
4. **Kontrollér forbindelse**（接続を確認）は公開 API を調べるだけで、私的セッションを転送しません。
5. 成功時は **Backend svarer · offentligt API nået**、**Privat login er fortsat i browseren** と表示されます。バックエンド応答・公開 API 到達・私的ログインはブラウザー内、という意味です。

これは過去の rc.1 Windows 受け入れで観測した表示です。公開 API 到達を示すだけで、私的アクセス、ノード参加承認、本番移行の証拠ではありません。このガイドはバックエンド配備や変更を指示しません。

失敗時は Internet 接続、プロファイル、Python/Node 前提条件を確認します。共有するのは秘匿情報を除いた説明のみです。ログはローカルパスを含み得ます。最初から ID 初期化や状態削除をしないでください。

実稼働 II エンドツーエンドは未検証です。クライアント公開だけを理由に、ローカルのアクセス保護修正が公開 Web アプリに配備済みと推測しないでください。

## 4. アクティビティ、一時停止、終了

![実際のローカル設定保存イベント。](../images/chroma-neural-activity.png)

アクティビティは保存や操作状態など、クライアントが記録したイベントです。イベントだけでは AI 品質の検証、公開、ポイント付与は証明されません。

対応ワーカーは一時停止と停止に従う必要があります。承認済みローカルジョブは制御された再起動後もキュー内の識別を維持します。受信ピア内容は不活性のままです。

**Afslut ChromaNeural**（ChromaNeural を終了）で完全終了します。トレイモードが有効かつ対応する場合、ウィンドウの閉じるボタンは非表示にするだけのことがあります。状態のバックアップ・移動前に終了してください。

## 5. ローカル AI と高度な作業

既存ローカル AI は **Udviklerværktøjer**（開発者ツール）にあります。対象テキストファイルを開くか保存します。**Local AI**、対応するローカルプロバイダー／モデル、指示を選び、正確な入力を承認します。提案を確認してから受理・保存します。提案だけではファイルを自動置換しません。

同梱 CPU/Qwen は Windows/Linux で利用できます。インストール済みローカル Ollama モデルは明示選択します。macOS に Qwen ランタイムは同梱されません。別プロバイダーへの自動フォールバックはありません。手動ローカル AI とネットワークの制御付きリソースプロファイルは別です。

この RC のキュー／ピア操作は高度な CLI 機能です。queue-ai、result、task-question、task-accept、task-reply、task-collect、task-status の --help と明示選択したローカル設定を使ってください。自動的な実稼働参加手段ではありません。

## 6. 私的ファイルと結果

明示的に選んだフォルダーだけで作業します。**Private II storage** は情報表示のみで、私的ファイル転送は行いません。ブラウザー所有者データとデスクトップファイルを結ぶ承認済みチャネルは未実装です。

ローカル結果は提案として確認できます。承認済みピアの回答も、SHA-256 一致だけで検証済みにはなりません。全体公開には検証、共有同意、役割、バックエンド受理が必要です。取得やレビューで ChromaPoints は付与されません。
